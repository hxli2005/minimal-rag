01 — The idea理念

A typical RAG pipeline decides in code.典型的 RAG 流水线，用代码做决定。

The query rewrite, the router, the retrievers, the top-k and the prompt are all fixed before the model ever sees the question.查询改写、路由、检索器、top-k、提示词，在模型看到问题之前就全部定死了。

Here, the model makes every decision.在这里，每个决定都交给模型。

What to search, whether to search again, what to read and when to stop — decided by the model, every turn, for every question.搜什么、要不要再搜、读哪里、何时停止——每道题、每一轮，都由模型判断。

The tools do the work.具体的活，交给工具。

Just two. search ranks original passages with BM25; read returns original text at any position. Both hand back document IDs and offsets the model can act on.只有两个：search 用 BM25 给原文段落排序；read 返回任意位置的原文。两者都返回文档 ID 和偏移，模型可以直接接着用。

Everything else is deleted.其余的，全部删掉。

No embeddings, no reranker, no router. What connects the model to its tools is a 66-line loop.没有向量、没有重排序、没有路由。连接模型和工具的，只是一个 66 行的循环。

03 — Capability能力

Same model. Better tools. 23 more right.同一个模型，换上更好的工具，多答对 23 题。

Same model, same BM25 index, same 230 queries. Replace our search/read with the benchmark's standard search tool and correct answers fall from 217 to 194. The gain comes from the interface, not only the model.同一模型、同一 BM25 索引、同样 230 道题。把我们的 search/read 换成基准自带的标准搜索工具，答对数从 217 掉到 194。提升来自工具接口，而不只是模型。

search(query, limit)

Ranks original passages with SQLite FTS5 BM25 and returns each with its document ID and character offset — real text, not a summary.用 SQLite FTS5 BM25 给原文段落排序，每条都带文档 ID 和字符偏移——给的是原文，不是摘要。

→ "Remediation SLA options + customer tier mapping…" · dsid_c838… · @0
read(document_id, offset, limit)

Returns original text at any position in any document. Where to look and how much to read is up to the model — like a person scrolling a file.返回任意文档任意位置的原文。读哪里、读多少由模型决定，就像人翻文件一样。

→ read("dsid_c838…", 3900, 6000) · "TTM (same across tiers) — Sev0: 30 minutes…"

06 — Fine print口径

      
The fine print, in large print.限制条款，用大字写。

    

  

  

    
01
Not yet official.还不是官方成绩。
Both submissions are with the maintainers. BrowseComp was scored by us with the official script; Enterprise official grading is pending.两份提交都在等维护方处理。BrowseComp 由本项目用官方脚本判分；Enterprise 等待官方判分。

    
02
Development sets, not held-out sets.回归集，不是留出集。
Both benchmarks were used during development; Enterprise dev/test is our own split. One generation per question except technical reruns; failures stay in the denominator.两个基准都在开发中用过；Enterprise 的 dev/test 是本项目自己的划分。除技术错误重跑外每题生成一次，失败计入分母。

    
03
Eight reruns, disclosed.8 道重跑，全部公开。
Timeouts, usage limits and SDK interrupts hit eight BrowseComp queries; each was rerun once with the same configuration. Counted as wrong: 93.37%.8 道 BrowseComp 题遇到超时、额度和 SDK 中断，各用相同配置重跑一次。全算错则为 93.37%。

    
04
Full runs used the Codex SDK.全量成绩来自 Codex SDK。
Codex injects extra tool definitions and multi-agent text; traces show no built-in tool calls. The direct API backend was only migration-tested on Enterprise dev30.Codex 会注入额外工具定义和多智能体说明，轨迹中没有内置工具调用。直连 API 后端只在 Enterprise dev30 上做过迁移验证。

    
05
One change to the judge script.判分脚本只改一处。
BrowseComp judging ran on one A800 with max_model_len=8192 added. The longest judge prompt is 1,216 tokens, so nothing is truncated.BrowseComp 判分在单张 A800 上运行，仅加入 max_model_len=8192；最长判分提示 1,216 token，不会截断。

    
06
A student project.个人学生项目。
Budget-limited. Every question keeps an inspectable trace, configuration and evaluation record.受预算限制。每道题都保留可检查的轨迹、配置和评测记录。
