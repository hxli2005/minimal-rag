# Enterprise 纯 BM25 回退诊断

**结论：优先处理纯 BM25 下的查询与候选探索。回退的主因是关键证据没有进入上下文，普遍加长阅读窗口不对症。** 43道由对变错的题中，32道涉及检索缺口（30道主导为检索，2道兼有回答缺口）；只有1道明确涉及“文档已定位，但关键段落未读到”，同时还存在已见事实遗漏。另有7道已见证据却漏写、错选或拒答，3道主要表现为判分口径敏感。

本轮保持纯BM25：没有修改主实现、提示、工具或原分数，没有新增模型调用。分析脚本和完整逐题材料在 `runs/bm25-unified-20261016/diagnosis/`。

- `qst_0210`：原问题直接BM25第1名就是包含DS公式的协议；新首条只有`"risk score" "release"`，目标不在前100，最后把其他评分方案列出来并拒答。
- `qst_0002`：正确指标为`stream.timebox_finalized`，新轨迹始终没出现该名称。旧组先见标题预览再取证；新首条query在BM25中目标其实排第9，但只取5条，随后改写查询而未取到它。
- `qst_0421`：只读到180秒旧协议，未找到明确更新为120秒的手册。原问题在BM25排第1；实际首query目标排第8，未被返回。

这32题是回退诊断子集，不是全400题的召回评测。原问题能把8题目标送入Top5，说明至少这部分损失不必靠更换BM25才能解释；**返回候选不等于8题一定答对**。另一方面，原问题仍有16题目标不在Top100，不能把所有损失简化成“首搜原题就解决”。

另重放43道回退题中历史首次有效命中的查询，当前BM25能把16个目标排进Top5、23个排进Top20、40个排进Top100。这里有些是历史多轮取证后才产生的查询，不能当成新agent可无条件得到的首搜词。旧组43道回退题里有19题至少一个参考文档首先来自`other_matches`标题指针；旧工具最多额外给15个候选标题，新主路径没有这层候选可见性。混合召回／重排和标题指针都可能帮助旧组定位，但现有轨迹不能拆出它们各自的提分。

### B. 真正“没读够”的明确案例：qst_0354

新组找到了《Metering → Invoice Reconciliation Playbook》，但只看到字符`4190:8190`；具体审批表在`3115:3339`：关闭账期账本修改需要三位指定批准人，超过10k美元或发票2%的计量错误退款需要另外两位批准人。旧组用read读了全文，新组没回读这部分，转而使用别的政策阈值。新组8轮就结束，尚未耗尽12轮预算。

同一道题的“只计费最终成功尝试”已在新首轮事故摘录`3557:4101`出现，却没有明确写入答案，因此属于**阅读不足＋已见事实遗漏**。这不支持统一增大所有摘录：从该手册offset=0读4000字符就足以覆盖审批表。

### D. 判分口径确实有波动，但没有据此改分

- 回退侧3题：`qst_0162`两答案几乎等义、事实向量完全相同却一对一错，且被称为unsupported的route/priority和pointer-copy在原文里；`qst_0269`两组同样不写briefly，audit messaging的近义表达被区别处理；`qst_0442`原文写Prefer，新答案照写却被判弱化，旧答案同样写prefer也未明说security例外却获判对。
- 改善侧7题也存在同类判分敏感：`qst_0191、0290、0348、0357、0399、0414、0433`。其中`qst_0290、0433`的两组事实向量完全相同；`qst_0357`两组均写了维度映射和通过Marketplace处理调整，判定却不同。
- 所有原判决仍保留。这里标记需要统一核查的判分边界，不发布“修正后准确率”，也不把裁判差异当成主要回退原因。

## 3. 调用为什么变多

| 行为 | 历史 | 纯BM25 |
| --- | ---: | ---: |
| search调用 | 1653 | 3342 |
| read调用 | 1016 | 452 |
| 模型调用 | 1830 | 2285 |
| 用满12轮的题数 | 29 | 56 |

30道未返回任何参考正文的回退题，模型调用从179增至349；43道回退题中30道用满12轮。轨迹表现为**搜索次数翻倍、阅读次数减少、反复找相似却不对应的问题材料**。回退题贡献新增模型调用189/455＝41.54%；两组都正确的281题也贡献213次，不能把全部额外开销都归于失败题。

旧工具描述明确允许自然语言问题并提示通过额外标题指针继续read；新工具描述强调BM25关键词。查询行为变化与这项工具变化相符，但旧／新模型适配器也不同，这里只将其列为机制线索，不宣称已做单因素因果证明。

## 4. 保持纯BM25的后续验证优先级

1. **先验证查询与候选探索。** 检查原问题首搜、保留时间／地区／对象／限定条件，以及如何利用BM25分页和不同查询视角；优先针对“原问题可排前列、实际改写却丢失”的失误模式。
2. **再验证已定位文档的定点阅读。** 对政策／审批类文档，检查模型是否主动读到条件和表格；qst_0354支持定点读缺失段，当前不支持统一扩大所有search/read返回。
3. **最后验证证据到答案的对齐。** 检查已经出现的精确名称、数字、例外和版本是否进入最终答案；找到关键事实后继续泛搜可能引入另一对象，需单独验证。
4. **判分边界单独整理。** 用一致规则核对已标记的近义答案和事实完整度阈值，避免把裁判尺度变化当成检索／回答能力变化。

以上是诊断结论与验证顺序，本轮没有实施任何候选修改或额外生成评测。
