## Summary
Runtime **1.21** introduces **Kernel Auto-Selection v2** ("selector v2") for GPU inference kernels. The selector chooses the best available kernel **per request** using a deterministic, explainable rule-based policy keyed on:
- **Model family / architecture** (e.g., Llama-like vs Mistral-like vs Qwen-like)
- **Sequence-length regime** (prefill-heavy, decode-heavy, mixed; plus long-context buckets)
- **GPU SKU** (e.g., A100 vs H100 vs L40S; including normalization of common cloud instance naming)

This release is focused on reducing **p95/p99 latency** and improving **throughput stability** across heterogeneous fleets without correctness regressions.

Selector v2 is shipped **behind feature gates** and includes fast rollback, per-model allow/deny controls, and guardrails for known-unstable driver/CUDA combinations.

---

## What’s New in 1.21
### 1) Kernel Auto-Selection v2 (gated)
- Expanded feature extraction: model-family tags + seq-length buckets + GPU SKU normalization.
- Explicit fallback hierarchy when a preferred kernel is unavailable or denied on a SKU.
- Deterministic decision logic and replay tests (same inputs => same kernel choice).

### 2) Selection Telemetry (sampled)
New per-request telemetry is available (sampling-controlled) to support debugging and rollout monitoring:
- chosen kernel
- candidate set (capped)
- feature vector (model family, seq bucket, gpu sku)
- fallback reason (if applicable)

### 3) Operator Controls & Debugging
- Force kernel selection for reproductions and customer escalations.
- Dump selection traces locally (or in canary pods) for triage.
- Hot-reloadable allow/deny rules (control plane) for fast mitigation.

## Configuration / Flags
Selector v2 is **off by default** in Runtime 1.21 unless enabled by the control plane gate or local runtime config (Dedicated/Private).

### Feature gates (Hosted / Dedicated via control plane)
Gate key:
- **kernel_selection.v2.enabled**

Scoped overrides supported:
- by model (exact model id)
- by model family (architecture tag)
- by region
- by GPU SKU

### Runtime config (Dedicated / Private)
The following keys are supported in `runtime.yaml` (or equivalent env var mapping).

**Core toggles**
- `kernel_selection.mode`: `v1` | `v2` | `auto` (default: `auto`)
- `kernel_selection.v2.enabled`: `true` | `false` (default: `false`)

**Allow/Deny lists (hot reload where supported)**
- `kernel_selection.v2.model_allowlist`: comma-separated model ids
- `kernel_selection.v2.model_denylist`: comma-separated model ids
- `kernel_selection.v2.gpu_sku_denylist`: comma-separated normalized SKUs (e.g., `A100-80GB`, `H100-SXM`, `L40S`)
- `kernel_selection.v2.driver_denylist`: comma-separated driver/CUDA tuples (example: `535.104.05+cuda12.2`)

**Telemetry**
- `kernel_selection.telemetry.enabled`: `true` | `false` (default: `true`)
- `kernel_selection.telemetry.sample_rate`: float 0.0–1.0 (default: `0.01`)
- `kernel_selection.telemetry.max_candidates`: integer (default: `6`)

### Runtime CLI flags (debug / reproduction)
Available in `redwood-runtime` binaries starting 1.21:
- `--kernel-selection=v1|v2|auto`
- `--force-kernel=<kernel_id>` (disables auto-selection)
- `--dump-kernel-selection=<path>` (writes per-request selection traces)
- `--kernel-selection-telemetry-sample-rate=<0.0-1.0>`

Notes:
- Forcing a kernel is intended for debugging and should not be used as a steady-state configuration unless directed by the runbook.
- Telemetry sampling does **not** affect selection behavior and does not introduce nondeterminism into decisions.
